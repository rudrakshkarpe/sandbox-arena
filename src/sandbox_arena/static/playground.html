KNOW WHAT YOU ARE MEASURING 04 / METHOD

Good measurements
have boundaries.

A transparent starting point for evaluating sandbox behavior.

01

A session, not a machine.

Every trial checks out a fresh Monty session from an existing worker pool. These measurements exclude process cold start and do not represent provisioning a remote container.

02

Time the whole boundary.

Setup measures session checkout. Execution measures the host call until it returns, including IPC and callbacks. Cleanup measures session release. All use a monotonic host clock.

03

Check the answer first.

Compute workloads have fixed expected outputs. Boundary workloads have explicit expected outcomes. A limited runaway loop is a passing boundary test; an unexpected error is a failure.

04

Keep failures visible.

Warmups never enter the summaries. Failed measurements are retained and counted. Median and ranges use passing trials; P95 uses nearest rank and requires 20 passing samples. Small samples remain exploratory.

05

Test a specific policy.

The fixture callback returns only three static records. OS access is denied. Passing these cases establishes the observed behavior of these tests; it is not a security certification.

06

Build a shared standard.

New adapters must declare capabilities, release resources, and preserve raw evidence. Public comparisons, cloud providers, concurrency suites, and live agent integrations are future milestones.
